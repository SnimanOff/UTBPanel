# UTBPanel

Лёгкая веб-панель для своих Go-ботов в Telegram.

## Полный бэкап

На странице «Сервер» владелец может создать полный архив, задать расписание
из пяти полей cron в UTC и число сохраняемых архивов (1–100). По умолчанию
расписание выключено, хранится до семи архивов. Старые архивы удаляются после
создания новых или уменьшения лимита хранения.

Панель передаёт ядру снимок `panel.db` через `VACUUM INTO` и каталог `pki/`.
Ядро добавляет снимок `core.db`, текущие версии ботов, снимки их SQLite-баз и,
по выбору, `DATA_DIR`. Манифест содержит версии компонентов и SHA-256 каждого
файла. Архив шифруется потоками блоков AES-256-GCM с отдельным производным
ключом для каждого файла; обрезанный или изменённый поток не принимается.

Архивы находятся в `/data/core/backups/full`. API владельца:
`GET/POST /api/backups`, `PUT /api/backups/settings` и
`GET /api/backups/{id}`. Время завершённого скачивания сохраняется отдельно;
HEAD-запрос скачиванием не считается.

Мастер-ключ не передаётся панели и не входит в архив. Сохраните его отдельно:

```sh
docker compose exec -T core core masterkey export > master.key
```

Восстановление выполняется по SSH на чистой установке, в которой ещё нет ботов:

```sh
docker compose exec -T core core masterkey import < master.key
docker compose exec -T core core backup restore < tgpanel-20261102-030000.backup
```

Команда передаёт архив ядру порциями, проверяет шифрование, контрольные суммы,
целостность всех SQLite-баз, бинарники и пару ключ/сертификат CA. До установки
снимки проверяются на совместимость с текущими миграциями. Затем ядро и панель
закрывают старые БД, заменяют данные с журналом отката и открывают их заново.
Ключи устройств сохраняются: CA и реестр берутся из архива. Сохранённые состояния
ботов восстанавливаются после подключения привратника, с его текущим сертификатом.
При смене адреса сервера поменяйте его в меню gate.

## Импорт бота

На главной кнопка «Импорт бота» принимает `.tgbot` и пароль. Сначала сервер
проверяет формат, хэши, целостность SQLite и статические бинарники Linux/amd64;
затем показывает настройки и имена секретов. Введите токен того же Telegram-бота
и новые значения секретов (для секретов-файлов выберите тип «Файл»).

Импорт выделяет новый локальный ID и UID, восстанавливает версии, базу, файлы,
пользователей, платежи, баны, список доступа, настройки, группу, пороги и
включённую в архив историю метрик. Значения переключателей ждут первой
регистрации SDK, после которой переподключения сохраняют новые правки.
Токен проверяется через `getMe`; до явного запуска старый вебхук не меняется.
Профиль Telegram восстанавливается перед запуском. Если Telegram откажет или
шаг панели не завершится, бот остаётся импортированным и остановленным, а
интерфейс показывает предупреждение и позволяет повторить оставшиеся действия.

API: `POST /api/imports/bots` с multipart-полями `file` и `password`, затем
`POST /api/imports/bots/{id}/apply` с `name`, `token`, `start` и `secrets`.
У секрета поля `kind` (`value` или `file`) и `value`; файлы передаются в base64.
Временные данные живут час, удаляются после успешного импорта или через
`DELETE /api/imports/bots/{id}`. Перезапуск ядра требует повторной загрузки.

## Экспорт бота

Во вкладке «Настройки» доступен экспорт `.tgbot`; на главной — экспорт всех
ботов отдельными архивами с общим паролем. Пароль из шести случайных слов
показывается при создании; можно задать свой. Сохраните его перед уходом со
страницы. Восстановить пароль на сервере нельзя.

Внутри зашифрованного age-архива лежит tar.gz: `manifest.json` с контрольными
суммами, `config.yaml`, текущий бинарник, снимок `bot.db` через `VACUUM INTO`,
`users.json` и `payments.json`. Можно включить все версии, историю метрик и
файлы из `DATA_DIR`. Символические ссылки и специальные файлы пропускаются.
Каталог секретов, токен и значения секретов не экспортируются.

`POST /api/exports/bots` принимает `bot_ids` (без списка — все боты),
`password` (пусто — создать), `files`, `metrics`, `all_versions`. В ответе
`password` и список `files` со сроком хранения; скачивание:
`GET /api/bots/{bot_id}/exports/{id}`. Шифрование и передача идут порциями,
целый архив не загружается в память. После скачивания интерфейс предлагает
остановить старого бота удержанием кнопки.

## Настройки одним документом

Во вкладке «Настройки» кнопка «Как документ» открывает YAML: его можно
скопировать, отредактировать, посмотреть diff и применить. В документ входят
переменные, имена секретов, поведение бота, профиль, лимиты, GitHub и пороги
уведомлений. Группа видна только для чтения. Значений секретов и токена нет.

API: `GET /api/bots/{id}/config`, `POST /api/bots/{id}/config/diff` и
`POST /api/bots/{id}/config/apply`. Последние принимают `version` из прочитанного
документа и одно из полей `document` (JSON) или `yaml` (строка). При чужой правке
возвращается `409 conflict`: нужно перечитать настройки. JSON Schema доступна
по `GET /api/bot-config/schema` и строится из OpenAPI.

Удаление имени из `secrets` удаляет сохранённое значение; новое имя сохраняется
как необходимый секрет и возвращается в `missing_secrets`, пока значение не
задано. Удаление ключа из `flags` сбрасывает переключатель к значению в коде.
Изменения окружения и секретов требуют рестарта. Telegram может принять только
часть полей профиля: API возвращает `applied: false`, ошибки полей и актуальный
документ; остальные настройки при этом ещё не применены.

## MCP

Адрес для MCP-клиента: `http://127.0.0.1:47100/mcp`, транспорт Streamable HTTP.
Передавайте `Authorization: Bearer <токен из меню gate>`. Gate проверяет токен
локально и подключается к панели с ключом устройства; токен на сервер не уходит.
Для MCP нужен отдельный токен: сессия браузера к этому адресу доступа не даёт.
Токен MCP действует только на `/mcp`, прямого доступа к REST API у него нет.

Каталог инструментов и входные схемы строятся из `api/openapi.yaml`.
Параметры пути и запроса находятся в корне аргументов, JSON-тело — в `body`.
Например: `get_bot` с `{"id": 7}`. Операции `never` не публикуются;
изменения пока закрыты. Вызовы и отказы попадают в аудит с источником `mcp`,
именем ключа и IP; значения аргументов в аудит не копируются.

## Проверка переноса и восстановления

Из каталога `backend`:

```sh
go test -tags=e2e -count=1 -run '^TestBackupAndTransfer$' -v ./e2e
```

Тест сам собирает и запускает ядро и панель с отдельными каталогами данных,
локальным заменителем Telegram и настоящими сертификатами mTLS. Проверяет
перенос настроек, пользователей, платежей, SQLite, файлов и секретов с новыми
значениями; отказ при неверном пароле и подмене байта; полный бэкап и команду
`core backup restore`; доступ к восстановленной панели с прежним ключом
устройства. Docker для этого сценария не нужен; он также включён в `e2e/run.sh`.

Каждый новый полный архив проверяется пробным восстановлением в `core/tmp`.
Результат виден рядом с архивом на странице «Сервер»; при нехватке места
появляется предупреждение о пропуске. Если архивы не скачивали семь дней,
панель напоминает сохранить копию вне сервера.

## Бот и прокси Bot API

Ядро передаёт боту `HTTPS_PROXY`, `HTTP_PROXY` и `SSL_CERT_FILE`: стандартный
`http.Client` Go сам идёт через прокси панели, и вызовы Bot API попадают в
метрики без правок кода. Проверено (`go test -tags libs ./internal/tgproxy`):

| библиотека | через прокси |
|---|---|
| github.com/go-telegram/bot v1.27 | да, без настроек |
| gopkg.in/telebot.v4 | да, без настроек |
| github.com/go-telegram-bot-api/telegram-bot-api/v5 | да, без настроек |

Если библиотека создаёт свой `http.Transport` без `Proxy: http.ProxyFromEnvironment`,
вызовы пойдут мимо панели: бот работает, но метрик Bot API у него не будет, и
панель предупредит «бот ходит мимо прокси».
