# UTBPanel

Лёгкая веб-панель для своих Go-ботов в Telegram. Три контейнера из одного
образа: привратник (`edge`) принимает вебхуки, ядро (`core`) запускает ботов,
панель (`panel`) — интерфейс, API и MCP. Вход без паролей: ключ доступа —
программа `gate.exe`, которую панель выдаёт на каждое устройство.

## Установка

Нужен сервер с Linux/amd64, Docker и Docker Compose. Открыть порты `443`
(панель, только mTLS), `8443` (вебхуки Telegram и GitHub) и `80`, если
сертификат для `:8443` берётся у Let's Encrypt.

```sh
git clone https://github.com/SnimanOff/UTBPanel.git && cd UTBPanel
cp .env.example .env
```

В `.env` указать:

- `PUBLIC_ADDR` — домен или IP сервера: на него Telegram шлёт вебхуки, к нему
  подключается gate;
- `DOMAIN` — домен для сертификата Let's Encrypt на `:8443`; пусто —
  самоподписанный сертификат (Telegram его принимает);
- `EDGE_VERSION`, `CORE_VERSION`, `PANEL_VERSION` — теги образа, лучше
  конкретная версия, а не `latest`;
- при необходимости `EDGE_MEM_LIMIT`, `CORE_MEM_LIMIT`, `PANEL_MEM_LIMIT`.

```sh
docker compose pull && docker compose up -d
```

### Ключ владельца

Первый ключ выпускается по SSH:

```sh
docker compose exec -T panel panel keys issue --owner --name home-pc > gate-home-pc.exe
```

Скопировать `gate-home-pc.exe` на свой компьютер с Windows и запустить в
течение 24 часов. Gate создаёт ключ устройства в TPM (без TPM — под DPAPI) и
показывает код из четырёх слов. Первое устройство подтверждается на сервере,
после сверки кода:

```sh
docker compose exec -T panel panel devices list
docker compose exec -T panel panel devices approve <id>
```

Дальше панель открывается через gate (значок в трее), остальные устройства
подтверждаются в самой панели удержанием кнопки. Дочерние ключи выпускаются
на странице «Ключи». Ключ отзывается сразу: `panel keys revoke <имя>`;
потерянный ключ владельца заменяется новым `keys issue --owner`.

### Gate на Linux и macOS

`keys issue` и страница «Ключи» выдают gate и для других систем:
`--os linux` (amd64), `--os macos` (Apple Silicon) или `--os macos-intel`.

```sh
docker compose exec -T panel panel keys issue --owner --name laptop --os linux > gate-laptop
chmod +x gate-laptop && ./gate-laptop
```

- Linux: ключ устройства создаётся в TPM 2.0 (`/dev/tpmrm0`, пользователь
  должен быть в группе `tss`). Без TPM ключ лежит в файле, зашифрованном
  секретом из GNOME Keyring или KWallet. Значок в трее — через
  StatusNotifierItem (KDE, GNOME с расширением AppIndicator), уведомления —
  `notify-send`, автозапуск — `~/.config/autostart`. Мини-окно открывается в
  браузере.
- macOS: ключ лежит в файле, зашифрованном секретом из связки ключей
  (Keychain). В образах из релизов gate для macOS собран с cgo и показывает
  значок в строке меню (уведомления — через `osascript`, автозапуск —
  `~/Library/LaunchAgents`); в образе, собранном локально, значка нет.
  Мини-окно открывается в браузере. Secure Enclave требует подписанного
  бинарника с правами на связку ключей и пока не используется. Скачанный
  файл снимите с карантина:
  `xattr -d com.apple.quarantine gate-laptop`.

Состояние gate хранится в `~/.config/tgpanel` (Linux) и
`~/Library/Application Support/tgpanel` (macOS).

### Мастер-ключ

Ядро шифрует токены и секреты мастер-ключом из тома `keys`. Сразу после
установки сохраните его вне сервера — без него бэкап не восстановить:

```sh
docker compose exec -T core core masterkey export > master.key
```

## Обновление

Каждый сервис обновляется отдельно по своему тегу в `.env`, поэтому случайный
`docker compose pull` или `up -d` не трогает ботов.

```sh
# панель: боты не перезапускаются
docker compose pull panel && docker compose up -d panel
# ядро: пара минут простоя, пользователям отвечает привратник по правилам техработ
docker compose pull core && docker compose up -d core
# привратник: нужно очень редко
docker compose pull edge && docker compose up -d edge
```

Перед этим поменять `PANEL_VERSION`, `CORE_VERSION` или `EDGE_VERSION`.
Пока ядро недоступно, платёжные и служебные апдейты копятся в очереди
привратника и доставляются ботам после старта ядра.

### Ядро без остановки ботов

Ядро можно заменить, не перезапуская ботов: новый процесс ядра принимает от
старого запущенных ботов, каналы их логов и порты прокси Bot API.

```sh
docker compose exec -T core core upgrade < core
```

`core` — бинарник ядра из нового релиза (Linux/amd64), его можно достать из
образа: `docker create --name tmp ghcr.io/snimanoff/utbpanel:<версия>`,
`docker cp tmp:/usr/local/bin/core . && docker rm tmp`. Пока процессы
меняются (обычно до секунды), апдейты принимает привратник, а SDK ботов
переподключается. Если новое ядро не стартовало за минуту, боты остаются у
старого. Затем укажите ту же версию в `CORE_VERSION`: при следующем
пересоздании контейнера ядро возьмётся из образа.

Внутри контейнера ядро работает под маленьким процессом-супервизором: он
забирает процессы ботов после выхода старого ядра и завершает контейнер
вместе с текущим ядром. `TGPANEL_NO_SUPERVISOR=1` отключает его (тогда
`core upgrade` недоступен).

### Автоматический деплой (CI/CD)

- Каждый пуш в `main` проверяет CI (`ci.yml`): тесты, линтер, фронтенд, e2e.
- Тег `vX.Y.Z` собирает образ `ghcr.io/snimanoff/utbpanel:X.Y.Z`
  (`release.yml`), после чего `deploy.yml` по SSH обновляет сервер
  скриптом `deploy/update.sh`: панель пересоздаётся, ядро меняется на месте
  через `core upgrade` (боты не останавливаются), привратник — только по
  запросу. В `.env` записываются новые `*_VERSION`, прежний `.env`
  остаётся рядом как `.env.before-<версия>`.
- Любую выпущенную версию можно развернуть вручную: Actions → deploy →
  Run workflow.

Для деплоя в репозитории нужны секреты `DEPLOY_HOST`, `DEPLOY_USER`,
`DEPLOY_SSH_KEY` (отдельный ключ, пользователь должен уметь запускать
docker), `DEPLOY_KNOWN_HOSTS` (вывод `ssh-keyscan <host>`) и переменные
`DEPLOY_PATH` (каталог с `docker-compose.yml`), при необходимости
`DEPLOY_PORT`. В Settings → Environments → production можно включить
подтверждение каждого деплоя.

Бэкап и восстановление — разделы «Полный бэкап» и «Экспорт бота» ниже.

## Как писать бота под панель

Бот — обычный webhook-бот на Go, который ничего не обязан знать о панели.
Эталоны: [`examples/echo-bot`](examples/echo-bot) (без зависимостей) и
[`examples/sdk-bot`](examples/sdk-bot) (с SDK). Те же правила читает
нейросеть: `/llms.txt` и `/docs/ai.md` панели генерируются из
`backend/api/openapi.yaml`.

Ядро передаёт боту переменные окружения:

| переменная | что это |
|---|---|
| `BOT_TOKEN` | токен бота; имя можно поменять в настройках бота |
| `PORT` | порт на 127.0.0.1, куда приходят вебхуки (`POST /`) |
| `WEBHOOK_SECRET` | сравнивать с заголовком `X-Telegram-Bot-Api-Secret-Token` |
| `WEBHOOK_URL` | публичный адрес вебхука, если нужен |
| `DATABASE_URL` | `file:…/bot.db` — своя SQLite-база бота |
| `DATA_DIR` | каталог для файлов бота (входит в бэкап по выбору) |
| `HTTPS_PROXY`, `SSL_CERT_FILE` | прокси Bot API панели, для метрик |
| `TZ` | всегда `UTC` |
| `GOMEMLIMIT` | из лимита памяти бота |
| `TGPANEL_SDK` | адрес SDK, только когда он нужен |
| `TGPANEL_CANARY` | `1` у новой версии на время канарейки |

Плюс переменные и секреты, заданные во вкладке «Настройки».

Правила:

- Все настройки — из переменных окружения. Токены и секреты в репозиторий не
  класть: их задают в панели, значения хранятся зашифрованными.
- Апдейты приходят вебхуком: его ставит ядро, и если бот сам вызывает
  `setWebhook`, это безвредно. Бот, написанный под polling, запускается без
  переделки: во вкладке «Настройки», блок «Приём апдейтов», включите
  «Включить вебхук», перезапуск не нужен.
  Telegram по-прежнему шлёт апдейты в панель вебхуком, а ядро отдаёт их боту в
  ответ на его `getUpdates` (offset, limit, timeout до 50 с, allowed_updates).
  Боту под вебхук включённый переключатель не мешает: пока бот не вызвал
  `getUpdates`, апдейты идут на его PORT как обычно.
  `deleteWebhook(drop_pending_updates)` очищает очередь, `getWebhookInfo`
  показывает пустой url. Порт и `WEBHOOK_SECRET` боту под polling не нужны: он
  считается готовым после первого `getUpdates`. Ответа в теле вебхука для него
  нет, а апдейты, которые ждут в очереди, теряются при перезапуске ядра.
- Каждый запрос на `PORT` сверять с `WEBHOOK_SECRET` (заголовок
  `X-Telegram-Bot-Api-Secret-Token`, сравнение за постоянное время) и без
  совпадения отвечать 401. Порт слушает 127.0.0.1, куда могут подключиться и
  другие боты панели: секрет отличает ядро от них.
- Ответ можно вернуть прямо в теле ответа на вебхук.
- Для Bot API — стандартный `http.Client` (или транспорт с
  `Proxy: http.ProxyFromEnvironment`), иначе вызовы пойдут мимо прокси и
  метрик Bot API не будет.
- База: без SDK — файл SQLite из `DATABASE_URL`, с SDK — `sdkdb.Open(kit)`.
- Без cgo: `modernc.org/sqlite` вместо `mattn/go-sqlite3`. Панель принимает
  только статические бинарники Linux/amd64:
  `CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -trimpath -o bot .`
- Миграции БД только обратно совместимые: добавлять можно, переименовывать и
  удалять — следующей версией. При автооткате старая версия работает с новой
  схемой, а на время канарейки обе версии работают одновременно.
- Если `TGPANEL_CANARY=1`, не запускать свои фоновые задачи (рассылки по
  таймеру, cron): на время канарейки они сработали бы дважды. Задачи через
  `sdk/tasks` панель запускает один раз сама.
- Корректно завершаться по SIGTERM.
- Обрабатывать `refunded_payment` и забирать товар: владелец может вернуть
  Stars из панели (вкладка «Пользователи» → «Платежи»).
- SDK (`github.com/SnimanOff/UTBPanel/backend/sdk`) подключать по желанию:
  готовность после миграций, своя БД через ядро, метрики, задачи по
  расписанию, переключатели без рестарта. Без панели SDK работает автономно.
  Подробно — [`backend/sdk/README.md`](backend/sdk/README.md).

### Обновление с тестом на тестовом боте

Вкладка бота «Деплой» → блок «Обновление», три шага:

1. **Новая версия.** Если текущая версия загружена бинарником, панель просит
   загрузить новый; если бот обновляется из GitHub Releases — проверить новый
   релиз (бинарник можно загрузить и вручную).
2. **Тест.** К боту привязывается отдельный тестовый бот: создайте его в
   @BotFather и вставьте токен. Он скрыт из общего списка ботов, у него свои
   порт и база, и он удаляется вместе с основным ботом. Тест идёт только на
   нём: выбранная версия копируется ему, он запускается на ней. По умолчанию
   он получает переменные и секреты основного, кроме своих `BOT_TOKEN` и
   `WEBHOOK_SECRET`. Проверка — в Telegram, логи — на странице тестового бота.
3. **Обновление.** «Всё работает — обновить» делает обычный деплой: бэкап
   базы, остановка текущей версии, запуск новой, минута наблюдения и
   автооткат. Тестовый бот после этого останавливается.

Из MCP то же самое: `start_trial`, `get_trial`, `promote_trial`, `stop_trial`.

### Автоудаление рассылки

При создании рассылки можно выбрать «Автоудаление» через 1–36 часов: в это
время ядро само отзывает рассылку, то есть удаляет сообщение у всех
получателей. Если рассылка ещё идёт, она удаляется сразу после окончания.
Больше 47 часов задать нельзя: Telegram даёт боту удалять свои сообщения
только 48 часов.

### Релизы из GitHub

В `examples/echo-bot` есть `.goreleaser.yaml` и `.github/workflows/release.yml`:
тег `v1.2.3` собирает `tar.gz` и `checksums.txt`. В настройках бота во вкладке
«Деплой» указать репозиторий и маску файла (`*linux_amd64*`); с автодеплоем
панель разворачивает новый релиз сама.

Настройки бота можно держать в репозитории: файл `tgpanel.yaml` — тот же
документ, что «Настройки → Как документ», без `version`. Его кладут в релиз
рядом с бинарником:

```yaml
release:
  extra_files:
    - glob: tgpanel.yaml
```

Профиль, тексты, пояс, переключатели, пороги и числа антифлуда применяются
вместе с деплоем. Изменения env, лимитов, GitHub, включения антифлуда и
закрытого режима ждут подтверждения diff владельцем, даже при автодеплое.

### Загрузка версии без GitHub

Во вкладке «Деплой» → «Загрузить» или из CI через gate с токеном MCP
(страница «Нейросети» показывает готовую команду):

```sh
curl -H "X-Panel: 1" -H "Authorization: Bearer <токен>" -F file=@bot \
  http://127.0.0.1:47100/api/bots/<id>/releases
```

Загрузка не разворачивает версию: деплой — отдельно, кнопкой или
инструментом `deploy_release` с подтверждением.


## Вход с телефона и доступ к отдельным ботам

Нужен домен (`DOMAIN` в `.env`) и открытый порт `WEB_PORT` (по умолчанию
`9443`). Сертификат Let's Encrypt выпускает привратник, панель получает его по
сокету. Без домена страница «Доступ» объясняет, что делать: WebAuthn не
работает на IP и с самоподписанным сертификатом.

1. Владелец на странице «Доступ» (только через gate) нажимает «Создать
   ссылку»: имя, роль и боты.
   - «Просмотр» — операции чтения выбранных ботов;
   - «Управление» — плюс рестарт, пауза, техработы, настройки и деплой этих
     ботов;
   - «Все права» (все боты) — как дочерний ключ, например для своего телефона.
   Ключи, бэкапы, рассылки, запись в базы и другие боты недоступны обеим
   ограниченным ролям.
2. Ссылка одноразовая, действует 24 часа. На телефоне — «Создать ключ входа»,
   Face ID или отпечаток, затем телефон показывает четыре слова.
3. Владелец сверяет слова в «Доступе» и подтверждает удержанием кнопки.
   Телефон сам открывает панель.

Дальше вход — `https://<домен>:9443` → «Войти». Сессия длится 12 часов.
Панель можно добавить на экран «Домой». «Отозвать» сразу удаляет ключи входа
и сессии. Все действия попадают в аудит с источником `web`.

## Сервисный бот

Страница «Сервер» → «Сервисный бот»: токен отдельного бота от BotFather и
уровень (только ошибки или ошибки и предупреждения). Токен хранится в ядре
зашифрованным. Получатель — Telegram ID владельца из настроек панели. Один раз
нажмите Start у этого бота и «Проверить». Повторы склеиваются, как в ленте.
Больше 20 сообщений в минуту бот не шлёт: остальные сворачиваются в одно.

## Исправление и отзыв рассылки

В течение 48 часов после запуска в истории рассылок есть кнопки «исправить»
(новый текст и кнопки, картинка остаётся) и «отозвать» (удалить сообщение у
всех получателей). Для этого ядро хранит `message_id` доставленных сообщений
48 часов.


## Полный бэкап

На странице «Сервер» владелец может создать полный архив, задать расписание
из пяти полей cron в UTC и число сохраняемых архивов (1–100). По умолчанию
расписание выключено, хранится до семи архивов. Старые архивы удаляются после
создания новых или уменьшения лимита хранения.

Панель передаёт ядру снимок `panel.db` через `VACUUM INTO` и каталог `pki/`.
Ядро добавляет снимок `core.db`, текущие версии ботов, снимки их SQLite-баз и,
по выбору, `DATA_DIR`. Манифест содержит версии компонентов и SHA-256 каждого
файла. Архив шифруется потоками блоков AES-256-GCM с отдельным производным
ключом для каждого файла; обрезанный или изменённый поток не принимается.

Архивы находятся в `/data/core/backups/full`. API владельца:
`GET/POST /api/backups`, `PUT /api/backups/settings` и
`GET /api/backups/{id}`. Время завершённого скачивания сохраняется отдельно;
HEAD-запрос скачиванием не считается.

Мастер-ключ не передаётся панели и не входит в архив. Сохраните его отдельно:

```sh
docker compose exec -T core core masterkey export > master.key
```

Восстановление выполняется по SSH на чистой установке, в которой ещё нет ботов:

```sh
docker compose exec -T core core masterkey import < master.key
docker compose exec -T core core backup restore < tgpanel-20261102-030000.backup
```

Команда передаёт архив ядру порциями, проверяет шифрование, контрольные суммы,
целостность всех SQLite-баз, бинарники и пару ключ/сертификат CA. До установки
снимки проверяются на совместимость с текущими миграциями. Затем ядро и панель
закрывают старые БД, заменяют данные с журналом отката и открывают их заново.
Ключи устройств сохраняются: CA и реестр берутся из архива. Сохранённые состояния
ботов восстанавливаются после подключения привратника, с его текущим сертификатом.
При смене адреса сервера поменяйте его в меню gate.

## Импорт бота

На главной кнопка «Импорт бота» принимает `.tgbot` и пароль. Сначала сервер
проверяет формат, хэши, целостность SQLite и статические бинарники Linux/amd64;
затем показывает настройки и имена секретов. Введите токен того же Telegram-бота
и новые значения секретов (для секретов-файлов выберите тип «Файл»).

Импорт выделяет новый локальный ID и UID, восстанавливает версии, базу, файлы,
пользователей, платежи, баны, список доступа, настройки, группу, пороги и
включённую в архив историю метрик. Значения переключателей ждут первой
регистрации SDK, после которой переподключения сохраняют новые правки.
Токен проверяется через `getMe`; до явного запуска старый вебхук не меняется.
Профиль Telegram восстанавливается перед запуском. Если Telegram откажет или
шаг панели не завершится, бот остаётся импортированным и остановленным, а
интерфейс показывает предупреждение и позволяет повторить оставшиеся действия.

API: `POST /api/imports/bots` с multipart-полями `file` и `password`, затем
`POST /api/imports/bots/{id}/apply` с `name`, `token`, `start` и `secrets`.
У секрета поля `kind` (`value` или `file`) и `value`; файлы передаются в base64.
Временные данные живут час, удаляются после успешного импорта или через
`DELETE /api/imports/bots/{id}`. Перезапуск ядра требует повторной загрузки.

## Экспорт бота

Во вкладке «Настройки» доступен экспорт `.tgbot`; на главной — экспорт всех
ботов отдельными архивами с общим паролем. Пароль из шести случайных слов
показывается при создании; можно задать свой. Сохраните его перед уходом со
страницы. Восстановить пароль на сервере нельзя.

Внутри зашифрованного age-архива лежит tar.gz: `manifest.json` с контрольными
суммами, `config.yaml`, текущий бинарник, снимок `bot.db` через `VACUUM INTO`,
`users.json` и `payments.json`. Можно включить все версии, историю метрик и
файлы из `DATA_DIR`. Символические ссылки и специальные файлы пропускаются.
Каталог секретов, токен и значения секретов не экспортируются.

`POST /api/exports/bots` принимает `bot_ids` (без списка — все боты),
`password` (пусто — создать), `files`, `metrics`, `all_versions`. В ответе
`password` и список `files` со сроком хранения; скачивание:
`GET /api/bots/{bot_id}/exports/{id}`. Шифрование и передача идут порциями,
целый архив не загружается в память. После скачивания интерфейс предлагает
остановить старого бота удержанием кнопки.

## Настройки одним документом

Во вкладке «Настройки» кнопка «Как документ» открывает YAML: его можно
скопировать, отредактировать, посмотреть diff и применить. В документ входят
переменные, имена секретов, поведение бота, профиль, лимиты, GitHub и пороги
уведомлений. Группа видна только для чтения. Значений секретов и токена нет.

API: `GET /api/bots/{id}/config`, `POST /api/bots/{id}/config/diff` и
`POST /api/bots/{id}/config/apply`. Последние принимают `version` из прочитанного
документа и одно из полей `document` (JSON) или `yaml` (строка). При чужой правке
возвращается `409 conflict`: нужно перечитать настройки. JSON Schema доступна
по `GET /api/bot-config/schema` и строится из OpenAPI.

Удаление имени из `secrets` удаляет сохранённое значение; новое имя сохраняется
как необходимый секрет и возвращается в `missing_secrets`, пока значение не
задано. Удаление ключа из `flags` сбрасывает переключатель к значению в коде.
Изменения окружения и секретов требуют рестарта. Telegram может принять только
часть полей профиля: API возвращает `applied: false`, ошибки полей и актуальный
документ; остальные настройки при этом ещё не применены.

## MCP

Адрес для MCP-клиента: `http://127.0.0.1:47100/mcp`, транспорт Streamable HTTP.
Передавайте `Authorization: Bearer <токен из меню gate>`. Gate проверяет токен
локально и подключается к панели с ключом устройства; токен на сервер не уходит.
Для MCP нужен отдельный токен: сессия браузера к этому адресу доступа не даёт.
Токен MCP действует только на `/mcp`, прямого доступа к REST API у него нет.

Каталог инструментов и входные схемы строятся из `api/openapi.yaml`.
Параметры пути и запроса находятся в корне аргументов, JSON-тело — в `body`.
Например: `get_bot` с `{"id": 7}`. Операции `never` не публикуются.
На странице «Нейросети» владелец задаёт режим каждой группы: `off`, `read`
(по умолчанию) или `full`. В полном режиме операции `write` выполняются сразу;
`confirm` требуют подтверждения владельца. Боты без группы и операции без
бота доступны только для чтения. Группы `off` скрыты также из общих списков.
Права перечитываются для каждого вызова. Вызовы и отказы попадают в аудит с источником `mcp`,
именем ключа и IP; значения аргументов в аудит не копируются.

Для диагностики одним запросом: `GET /api/bots/{id}/overview`, инструмент
`get_bot_overview`. Сводка содержит статус и аптайм процесса, последние ошибки,
паники, состояние вебхука, деплой и отчёт, пороги, действующие лимиты и их
заполнение, отложенные апдейты и канарейку. При недоступности Telegram
возвращается сохранённое состояние вебхука с `webhook_live: false` и ошибкой.

## Проверка переноса и восстановления

Из каталога `backend`:

```sh
go test -tags=e2e -count=1 -run '^TestBackupAndTransfer$' -v ./e2e
```

Тест сам собирает и запускает ядро и панель с отдельными каталогами данных,
локальным заменителем Telegram и настоящими сертификатами mTLS. Проверяет
перенос настроек, пользователей, платежей, SQLite, файлов и секретов с новыми
значениями; отказ при неверном пароле и подмене байта; полный бэкап и команду
`core backup restore`; доступ к восстановленной панели с прежним ключом
устройства. Docker для этого сценария не нужен; он также включён в `e2e/run.sh`.

Каждый новый полный архив проверяется пробным восстановлением в `core/tmp`.
Результат виден рядом с архивом на странице «Сервер»; при нехватке места
появляется предупреждение о пропуске. Если архивы не скачивали семь дней,
панель напоминает сохранить копию вне сервера.

## Бот и прокси Bot API

Ядро передаёт боту `HTTPS_PROXY`, `HTTP_PROXY` и `SSL_CERT_FILE`: стандартный
`http.Client` Go сам идёт через прокси панели, и вызовы Bot API попадают в
метрики без правок кода. Проверено (`go test -tags libs ./internal/tgproxy`):

| библиотека | через прокси |
|---|---|
| github.com/go-telegram/bot v1.27 | да, без настроек |
| gopkg.in/telebot.v4 | да, без настроек |
| github.com/go-telegram-bot-api/telegram-bot-api/v5 | да, без настроек |

Если библиотека создаёт свой `http.Transport` без `Proxy: http.ProxyFromEnvironment`,
вызовы пойдут мимо панели: бот работает, но метрик Bot API у него не будет, и
панель предупредит «бот ходит мимо прокси».
