# UTBPanel

Лёгкая веб-панель для своих Go-ботов в Telegram.

## Настройки одним документом

Во вкладке «Настройки» кнопка «Как документ» открывает YAML: его можно
скопировать, отредактировать, посмотреть diff и применить. В документ входят
переменные, имена секретов, поведение бота, профиль, лимиты, GitHub и пороги
уведомлений. Группа видна только для чтения. Значений секретов и токена нет.

API: `GET /api/bots/{id}/config`, `POST /api/bots/{id}/config/diff` и
`POST /api/bots/{id}/config/apply`. Последние принимают `version` из прочитанного
документа и одно из полей `document` (JSON) или `yaml` (строка). При чужой правке
возвращается `409 conflict`: нужно перечитать настройки. JSON Schema доступна
по `GET /api/bot-config/schema` и строится из OpenAPI.

Удаление имени из `secrets` удаляет сохранённое значение; новое имя сохраняется
как необходимый секрет и возвращается в `missing_secrets`, пока значение не
задано. Удаление ключа из `flags` сбрасывает переключатель к значению в коде.
Изменения окружения и секретов требуют рестарта. Telegram может принять только
часть полей профиля: API возвращает `applied: false`, ошибки полей и актуальный
документ; остальные настройки при этом ещё не применены.

## Бот и прокси Bot API

Ядро передаёт боту `HTTPS_PROXY`, `HTTP_PROXY` и `SSL_CERT_FILE`: стандартный
`http.Client` Go сам идёт через прокси панели, и вызовы Bot API попадают в
метрики без правок кода. Проверено (`go test -tags libs ./internal/tgproxy`):

| библиотека | через прокси |
|---|---|
| github.com/go-telegram/bot v1.27 | да, без настроек |
| gopkg.in/telebot.v4 | да, без настроек |
| github.com/go-telegram-bot-api/telegram-bot-api/v5 | да, без настроек |

Если библиотека создаёт свой `http.Transport` без `Proxy: http.ProxyFromEnvironment`,
вызовы пойдут мимо панели: бот работает, но метрик Bot API у него не будет, и
панель предупредит «бот ходит мимо прокси».
